# CaseFlow 비전 AI: 외관 불량 + 불량 원인 판정

검사 셀에 도착한 케이스(본체 + 뚜껑)의 상면 카메라 이미지를 보고, 정상인지 아니면 6가지 불량 원인 중 무엇인지 판정합니다.
판정은 MES 서버(`AiInspector`)에서 한 번만 내립니다. 그 판정이 OIP 데스크탑 PLC의 유일한 판정이고, 웹 트윈은 같은 순번에 같은 판정을 따릅니다.

| 클래스 | 뜻 |
|---|---|
| OK | 정상 |
| LID_MISSING | 뚜껑 누락 |
| LID_MISALIGNED | 뚜껑 어긋남 (밀림·회전·들뜸) |
| SCRATCH | 스크래치 |
| CRACK | 크랙 |
| CONTAMINATION | 오염 (기름·분진·녹물) |
| DENT | 찍힘·변형 |

## 파이프라인

1. **`gen.ts` + `render.mjs`**: OIP가 화물 상자를 그릴 때 쓰는 메쉬(`cargoBoxMesh`)와 골판지 텍스처를 그대로 씁니다.
   - 본체는 0.3×0.3×0.15 m `#d5a86b`, 뚜껑은 0.1 m `#367db5`입니다.
   - 컨베이어 벨트와 레일 위에 케이스를 렌더링합니다.
   - 조명, 카메라, 위치, 색조는 무작위로 바꾸고, 불량은 텍스처와 노멀맵에 그려 넣습니다.
   - 빌드: `rolldown gen.ts -o gen.js -f iife -p browser` (OIP 저장소가 `../oip`에 있어야 합니다)
   - 렌더링: `node render.mjs <out> <클래스당 장수> <시드 시작> [포트] [클래스,...]`
2. **`camera.py`**: 카메라 열화를 흉내 냅니다(센서 노이즈, 약한 흐림, JPEG). `test_hard`는 더 나쁜 조건(밝기, 흐림, 노이즈, 압축)으로 만든 시험셋입니다.
3. **`train.py <실험>`**: 실험은 scratch128, mnv3_128, mnv3_128_aug, mnv3_192_aug 네 가지입니다.
   - 실험마다 정확도, 불량 유출, 과검출, 원인 정확도, ECE, 혼동행렬을 기록합니다.
4. **`export.py <실험> <resources>`**: 다음을 수행합니다.
   - 검증셋에서 비용 최소 임계값을 고릅니다.
   - ONNX로 내보내고 PyTorch와 출력 오차(≤1e-3)를 검증합니다.
   - `model.json`(모델 카드)과 운영 이미지 풀을 MES 리소스에 넣습니다.

## 데이터 분할 (모두 다른 시드)

| 분할 | 장수 | 용도 |
|---|---|---|
| train | 클래스당 600장 (4,200장) | 학습 |
| val | 클래스당 150장 | 학습 곡선 관찰, 온도·임계값 결정 |
| test, test_hard | 클래스당 150장 | 최종 성능, 한 번만 측정 |
| pool | 불량 클래스당 40장 + 정상 300장 | 공정 중 판정에만 사용. 학습·검증·시험에는 쓰지 않음 |

## 결과

`experiments/`에 실험별 지표가 있고, 최종 모델 카드는 `mes/backend/src/main/resources/ai/model.json`에 있습니다. 설정마다의 근거와 이전 대비 개선 내용은 프로젝트 진행 정리본 PDF 11장에 정리했습니다.
