# CASEFLOW | 소형 케이스 조립·검사·포장 MES

본체와 뚜껑을 반복 공급하고 로봇으로 조립한 뒤, 검사 결과에 따라 불량품을 분류하거나 양품을 포장·출고하는 공정입니다. 작업지시의 **목표 양품 수량**에 도달할 때까지 불량품 수만큼 다음 세트를 보충합니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `oip/project` | OIP 현장 배치, 센서·출력 배선, IEC 61131-3 Structured Text 제어 프로그램과 공정 시험 |
| `mes/backend` | Spring Boot API, OPC UA 수집, 작업지시·BOM·LOT·자재·품질·출고 이력 |
| `mes/web` | React MES 화면과 OIP 위치 데이터를 따르는 Three.js 3D 현장 뷰 |
| `indy` | ROS 2 Indy7 관절 동작과 제어기 완료 신호를 연결하는 브리지 |
| `oip/background-runtime.patch` | OIP 최소화 시 시뮬레이션 일시 정지를 해제하는 데스크톱 패치 |
| `docs` | 진행 보고서와 다음 작업 인계서, 사용한 OIP MIT 라이선스 |

## 현장과 화면의 관계

OIP 실행기의 PLC와 물리 시뮬레이션이 제어 상태의 단일 기준입니다. MES는 OPC UA로 작업 상태와 생산 수량을 받고, 로컬 에이전트에서 설비 배치와 이동 중 제품의 위치를 받아 3D 뷰에 표시합니다. MES의 3D 뷰는 회전·확대·설비 선택이 가능하며 설비 형상은 경량 시각화입니다. OIP 원본 화면 자체를 웹에서 다시 실행하지 않으므로 별도 시뮬레이션의 상태 불일치는 없습니다.

## 로컬 실행

1. OIP 데스크톱에서 `oip/project`를 열고 Play 및 OPC UA 서버(`4843`)를 켭니다. OIP 로컬 에이전트(`5189`)도 켭니다.
2. `mes/backend`에서 Java 25를 사용해 `./mvnw spring-boot:run`을 실행합니다. 기본 DB는 로컬 H2 파일입니다.
3. `mes/web`에서 `npm ci && npm run dev`를 실행하고 `http://127.0.0.1:5173`을 엽니다.
4. Indy7을 연동할 때는 `indy/README.md`의 ROS 2 Jazzy·Gazebo 절차를 따릅니다.

새 작업 시작 전에 기존 OIP 누적 카운터를 초기화해야 합니다. 실행 중인 작업을 초기화하면 작업 실적이 어긋날 수 있으므로 작업지시 상태를 먼저 확인합니다.

## 검증 범위와 남은 부분

- 계획 → 승인 → 작업지시 → 가동 → 재고 차감 → 품질 → 포장 → 출고까지 실측했습니다.
- OIP 공정 시험, MES 백엔드 시험, 웹 빌드가 통과했습니다.
- 현재 검사는 규칙 기반 판정입니다. 실제 케이스 사진을 학습한 영상 불량 판정과 원인 분류는 아직 적용하지 않았습니다.
- Indy7 관절 궤적과 OIP 완료 신호를 연동했습니다. 그리퍼와 실제 부품 픽업 좌표는 아직 보정하지 않았습니다.
- 3D 화면의 설비 외형과 차량 적재는 시각화이며, 제품별 물리 ID를 출고 차량까지 보존하는 기능은 후속 작업입니다.
- OIP를 종료하면 로컬 PLC와 시뮬레이션도 종료됩니다. 배포형 MES만으로 공정을 가동하려면 OIP 실행기를 상주 서비스로 운영하고 원격 연결 경로를 추가해야 합니다.
